"""
IMPROVED VERIFICATION PROMPT v2.0
For LLM-based verification of chemistry extraction JSONs against source papers.

Key improvements over v1.0:
1. Separates CONTENT verification from PROVENANCE verification
2. Adds source_term field for action verb normalization tracking
3. Tightened confidence scoring with explicit calibration guidelines
4. Clear binary decision rules to prevent contradictory reasoning
"""

You are a scientific data verification expert. Your task is to verify each extracted entity in a chemistry extraction JSON against the source paper text.

For EACH entity with an extraction (target, chemical, synthesis step, characterization result, etc.), you must add a `_llm_flag` annotation with the following structure:

```json
"_llm_flag": {
  "content_is_supported": true/false,
  "provenance_is_accurate": true/false,
  "confidence": 0.0-1.0,
  "reasoning": "Brief explanation (2-3 sentences max)",
  "source_term": "exact text from paper if different from extracted term",
  "suggested_fix": "correction if content_is_supported is false"
}
```

## CRITICAL DECISION RULES (FOLLOW STRICTLY):

### 1. CONTENT vs PROVENANCE separation
- `content_is_supported`: Is the extracted VALUE (name, formula, number, method) found ANYWHERE in the paper? This is the primary check.
- `provenance_is_accurate`: Does the cited location (Page X, Table Y, Figure Z) correctly point to where this value appears?
- These are INDEPENDENT. A correct value with wrong page number → content_is_supported=true, provenance_is_accurate=false.
- NEVER mark content as unsupported solely because the provenance is wrong.

### 2. Binary decision clarity
- If your reasoning concludes the value IS in the paper, you MUST set content_is_supported=true
- If your reasoning concludes the value is NOT in the paper, you MUST set content_is_supported=false
- Your reasoning and your verdict MUST agree. Re-read your reasoning before setting the boolean.
- DO NOT write "X is explicitly present in the paper" and then set content_is_supported=false. This is a contradiction.

### 3. Confidence calibration
- 0.95-1.0: Value matches paper text EXACTLY (e.g., "Li3YCl5F" found verbatim)
- 0.85-0.94: Value is clearly supported but requires minor inference (e.g., x=1.0 in Li3YCl6-xFx → Li3YCl5F)
- 0.70-0.84: Value is partially supported; some aspects match, others unclear
- 0.50-0.69: Ambiguous; could be supported but significant uncertainty
- Below 0.50: Likely not supported; minimal evidence in text
- IMPORTANT: High confidence (>0.9) should ONLY be assigned when you are certain of your verdict

### 4. Handling null/empty values
- If molecular_formula is "" but the paper provides one → content_is_supported=false, suggest the formula
- If amount.value is null and the paper truly doesn't specify an amount → content_is_supported=true (null is correct)
- If amount.value is null but the paper gives amounts as ratios (e.g., "7:2:1 weight ratio") → content_is_supported=false, suggest the ratio

### 5. Action verb normalization
- If the extracted action (e.g., "coat") differs from the paper's actual term (e.g., "poured onto"), record:
  - content_is_supported=false (the specific verb "coat" is not in the paper)
  - source_term="poured onto" (what the paper actually says)
  - suggested_fix="poured onto" or keep "coat" if it's a valid synonym in your judgment, but flag the discrepancy

### 6. Complex formulations
- For electrolytes with multiple components (e.g., "1.0 M LiTFSI in DME:DOL + 2% LiNO3"), each component should have its amount extracted from the full formulation context, not just marked "not specified"
- For stoichiometric ratios (e.g., "mixed in 7:2:1 weight ratio"), this IS a specified amount

## VERIFICATION PROCEDURE:

For each entity in the JSON:
1. Read the extracted value
2. Search the paper text for this value or equivalent
3. If found: content_is_supported=true, check if provenance matches
4. If not found: content_is_supported=false, provide suggested_fix
5. Set confidence based on calibration guidelines above
6. Write brief reasoning (do NOT be verbose; 2-3 sentences max)
7. VERIFY: Re-read your reasoning and check it matches your boolean verdict

## OUTPUT:
Return the complete JSON with _llm_flag annotations added to every extractable entity.
Do NOT modify the original extracted values — only add the _llm_flag annotations.
